# M6: Repair and evaluation

**Goal:** diagnose failed runs, propose gate-passing repairs, and measure the system.

## Scope

- Failure classifier over the last 200 log lines + commit diff. Categories:
  `invalid_yaml`, `missing_dependency`, `runtime_version`, `test_failure`, `permissions`,
  `secret_missing`, `deprecated_action`, `network_transient`, `resource_limit`,
  `deployment_health`, `unknown`. Each with confidence and evidence.
- Repair proposals edit the plan, never YAML, then go through M3 compile, M4 gate and
  sandbox, and M5 PR.
- `network_transient` suggests a re-run; `test_failure` is routed to the developer.
- Evaluation harness: ~30 real open-source repos, three approaches (template-only,
  LLM-only, AegisFlow), metrics in `docs/design.md#evaluation`.

## Exit test

Seeded failures (wrong package manager, outdated runtime, deprecated Action, missing
secret, real failing test) are handled correctly, and the evaluation report compares all
three approaches on every metric.
