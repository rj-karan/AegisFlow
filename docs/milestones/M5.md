# M5: Pull request and monitor

**Goal:** install the pipeline through a real PR and record what happens after merge.

## Scope

- PR operation: create branch, commit workflow files, open PR with generated description
  (tools and why, validation results, required secrets, rollback).
- Respect branch protection; surface missing App permissions precisely.
- Operation state machine: `not_connected`, `not_configured`, `ready`, `queued`, `running`,
  `awaiting_approval`, `succeeded`, `failed`, `cancelled`, `stale`.
- Webhooks for `workflow_run` and `check_run`; store job outcomes and durations in
  `workflow_runs`.
- Dashboard: operation timeline and run history per repo.

## Exit test

A PR opened by AegisFlow on a real repo is merged by a human, and the first run after
merge appears in the dashboard with per-job durations.
